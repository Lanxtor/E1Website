Wo

Standardmäßig Cloud, Ihre eigenen Server, wenn die Richtlinie es verlangt

E1 läuft an drei Orten: in der E1 Cloud, betrieben von LANXTOR; in Ihrem eigenen Microsoft-Azure-Abonnement; oder lokal in Ihrem eigenen Rechenzentrum. In jedem ist es dasselbe E1.

Die meisten Teams beginnen in der E1 Cloud, gehostet von LANXTOR in der EU. Wenn Verträge, Exportvorschriften oder Unternehmensrichtlinien vorgeben, wo Engineering-Daten gehalten werden müssen, legt eine Enterprise-Installation sie dorthin: Datensouveränität in Ihrem eigenen Abonnement, Ihrer Region und Ihrem Netzwerk. Amazon Web Services, Google Cloud und Alibaba Cloud folgen als weitere Möglichkeiten.

In Ihrem eigenen Azure gibt es zwei Möglichkeiten, es zu betreiben. Ihre IT installiert und betreibt es mit den Anleitungen von LANXTOR, oder LANXTOR betreibt es für Sie in Ihrem Azure. In beiden Fällen gehören Ihnen das Abonnement, die Daten und die Azure-Rechnung.

Die Statusleiste in E1 nennt immer, wo die Projekte gespeichert sind, zum Beispiel Microsoft Azure oder PostgreSQL mit dem Namen Ihres Datenbankservers, sodass jeder sehen kann, in welcher Installation er ist.

Installation

Wie eine Installation eingerichtet wird

In E1 laden die Owner und Administrators Ihrer Organisation alles zur Installation von E1 aus ihrem Account in der E1 Cloud unter Own installation herunter, sobald LANXTOR es für die Organisation eingeschaltet hat.

Das Installationspaket ist eine ZIP-Datei: die neueste Version von E1, Ihr Zugang zu den Releases von E1 und ein kurzes Start here. Ihre IT entpackt sie in der Azure Cloud Shell und folgt den Installationsschritten; Ihr eigenes E1 wird in Ihrem Abonnement erstellt und gibt seine Adresse aus. Jeder Download verlangt, dass Sie mit einem Passkey bestätigen, dass Sie es sind, und wird im Audit-Protokoll Ihrer Organisation festgehalten.

Eine neue Installation hat keinen Owner. Nur die Person, deren E-Mail-Adresse als Betreiber genannt wurde, kann sie durch erstes Anmelden beanspruchen; sonst niemand. Die Desktop-App verbindet sich über seine Adresse mit Ihrer Installation, und die Personen nutzen sie im Browser wie die E1 Cloud.

Lizenz

Eine signierte Lizenzdatei, offline geprüft

In Ihrer eigenen Installation stammen der Plan, die Plätze jeder Lizenz, die Inhaltspakete und die Termine aus einer von LANXTOR signierten Lizenzdatei. E1 prüft sie selbst, offline.

Der Owner lädt die Lizenzdatei unter Account → Own installation in der E1 Cloud herunter und lädt sie einmal unter File → Organization… → Members, und wieder jedes Mal, wenn LANXTOR eine erneuerte ausstellt. Plan und Plätze gelten sofort, und das Laden steht im Audit-Protokoll. Eine Datei ist an die Adresse Ihrer Installation gebunden. E1 lehnt eine Datei ab, die nach dem Signieren geändert wurde, eine Datei für eine andere Adresse und eine, die noch nicht gültig ist, und sagt, warum.

Dreißig Tage vor dem Ende einer Lizenz erhalten alle Owner und Administrators eine Mitteilung in der Inbox. Nach dem Ende folgt eine Karenzzeit, 30 Tage, sofern Ihr Vertrag nichts anderes sagt, in der alles noch funktioniert. Danach ist die Installation schreibgeschützt, bis eine erneuerte Datei geladen wird: Alle können weiterhin alles öffnen, ansehen und exportieren. E1 wird nie gesperrt.

Anmeldung

Unternehmens-Single-Sign-on und Verzeichnissynchronisierung

In E1 melden sich Kollegen mit ihrem Firmenkonto über jeden OpenID-Connect-Anbieter an, und Ihr Firmenverzeichnis erstellt, aktualisiert und deaktiviert sie in E1 mit SCIM 2.0.

Owner und Administrators richten die Anmeldung unter File → Organization… → Sign-on mit Ihrer IT ein, zum Beispiel mit Okta, Microsoft Entra ID, Google Workspace, Keycloak oder ADFS. Die Anmeldung funktioniert für die verifizierten E-Mail-Domänen Ihres Unternehmens, und Only this way macht sie für diese zum einzigen Zugang. Das Anmelden mit einem Microsoft-Firmenkonto ist ebenfalls möglich.

Die Verzeichnissynchronisierung deaktiviert jeden, der geht: Mitgliedschaft, Lizenz und Rollen enden, und die Person kann sich nicht mehr anmelden, während ihr Verlauf bleibt. Verzeichnisgruppen werden zu E1-Gruppen, und eine Gruppe kann eine Lizenz vergeben, zum Beispiel E1-Editors → Editor. Owner und Administrators bestätigen weiterhin mit einem Passkey.

Kontrolle

Audit, Zugriff und Integration nach Ihren Regeln

In E1 sehen Administratoren, wer was getan hat: Der Tab Audit listet wichtige Ereignisse und jede an ein KI-Modell gesendete Anfrage auf, und der Zugriffsverlauf zeigt jede Änderung an Mitgliedern, Lizenzen, Gruppen und Rollen mit vorher und nachher.

Der E1-Support hat keinen Zugriff auf Ihre Daten. Bittet er für einen Supportfall um Zugriff, wird nichts gegeben, bis ein Owner oder Administrator ihn für einige Stunden genehmigt, schreibgeschützt oder mit Änderungen; er endet sofort mit End. Alles, was der Support tut, steht im Verlauf und im Audit-Protokoll.

Andere Systeme verbinden sich über die API von E1 mit Zugriffstokens und Dienstkonten, über signierte Webhooks und einen Änderungs-Feed oder über MQTT-, AMQP- und Kafka-Broker. In Ihrer eigenen Installation kann ein Broker in Ihrem eigenen Netzwerk liegen. Owner und Administrators können die ganze Organisation jederzeit in offenen Formaten exportieren.

  • Daten: Ihre eigene PostgreSQL-Datenbank, in Ihrem Abonnement oder Rechenzentrum.
  • Updates: Sie installieren sich in der Stunde, die Sie wählen, von selbst; dringende Korrekturen innerhalb einer Stunde.
  • Lizenzierung: Single Sign-on, viele Lizenzen, eine Rechnung.

Fragen

Fragen, die Ingenieure stellen.

Kann E1 lokal betrieben werden?

Ja. Neben der E1 Cloud und Ihrem eigenen Microsoft Azure kann E1 lokal auf Ihren eigenen Servern mit Ihrer eigenen PostgreSQL-Datenbank installiert werden. Kontaktieren Sie den Vertrieb, um es zu planen.

In welchen Clouds können wir E1 installieren?

Heute in Microsoft Azure. Amazon Web Services, Google Cloud und Alibaba Cloud folgen.

Hält LANXTOR unsere Daten bei einer eigenen Installation?

Nein. In Ihrem eigenen Azure gehören Ihnen das Abonnement, die Daten und die Rechnung, egal ob Ihre IT E1 betreibt oder LANXTOR es dort für Sie betreibt. Der E1-Support sieht Ihre Projekte nur, wenn ein Owner oder Administrator eine Supportanfrage genehmigt.

Muss E1 LANXTOR aufrufen, um die Lizenz zu prüfen?

Nein. Die Lizenzdatei wird von LANXTOR signiert und von E1 selbst offline geprüft. Sie laden eine erneuerte Datei, wenn LANXTOR eine ausstellt.

Was passiert, wenn unsere Lizenzdatei abläuft?

Es folgt eine Karenzzeit, 30 Tage, sofern Ihr Vertrag nichts anderes sagt, in der alles funktioniert. Danach ist die Installation schreibgeschützt: Alles kann geöffnet, angesehen und exportiert, aber nicht geändert werden, bis der Owner eine erneuerte Datei lädt.

Welche Anmeldeanbieter funktionieren?

Jeder OpenID-Connect-Anbieter, etwa Okta, Microsoft Entra ID, Google Workspace, Keycloak oder ADFS, mit SCIM-2.0-Verzeichnissynchronisierung. Microsoft-Firmenkonten funktionieren ebenfalls.

Wie werden Updates installiert?

Updates installieren sich in der Stunde, die Sie wählen, von selbst, dringende Korrekturen innerhalb einer Stunde. Wird Ihr Server aktualisiert, teilt E1 im Browser und in der Desktop-App jedem Benutzer mit, dass eine neue Version bereit ist.
