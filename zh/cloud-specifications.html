每晚测试

E1 的每一项更改都会按照固定的性能预算计时，变慢的构建会被判定失败。每周会运行一次 100 位工程师同时工作的压力测试，以及一次一小时的浸泡测试。

所有人实时同步

一位工程师所做的更改约一秒内即可由服务器推送给所有打开该项目的人，无需重新加载。

随负载扩展

E1 服务器在繁忙时自动增加容量，并始终保持运行，因此不存在冷启动。每隔几秒进行一次健康检查，替换停止响应的服务器。

背后的服务器

全部采用独享核心：E1 Cloud 中没有任何组件运行在可突增或共享核心的机器上。

  • 数据库Azure Database for PostgreSQL 16，最新一代 Intel 上的常规用途层级：仅限独享核心
  • 规模2 至 96 个独享 vCore，8 至 384 GB 内存，随同时工作的工程师人数提升
  • 数据库存储SSD，128 GB 起，自动增长
  • E1 服务器每台 2 vCPU、4 GB 的服务器，按负载增加

这些规格与系统要求中的相同，E1 Cloud 和您自己的安装都适用。

在我们的负载测试中测得。E1 Cloud 中的时间取决于您的项目规模、同时工作的人数以及您的网络连接。

安全

安全源于设计，层层防护。

部分保护由 Microsoft Azure 提供，其余则由我们内置于 E1 本身。它们共同保护您的数据，从登录到存储。

登录

  • 通过 Microsoft Entra External ID 登录，可使用贵公司的 Microsoft 帐户，或贵公司自己的登录方式（OpenID Connect，并通过 SCIM 2.0 进行目录同步）。E1 不保存任何密码。
  • 所有者和管理员在使用其权限之前须通过通行密钥确认。
  • 敏感操作（例如授予管理员权限或导出全部内容）会在您上次登录超过 15 分钟时要求您重新登录。
  • 会话在 12 小时后结束。

加密

  • 仅限 HTTPS，并启用 HSTS：您的浏览器绝不会以未加密方式与 E1 通信。
  • E1 服务器通过 TLS 访问数据库并执行完整的证书校验，访问存储时仅使用 TLS 1.2 或更高版本。
  • 数据库、文件、备份和 Key Vault 均由 Microsoft Azure 使用 AES-256 进行静态加密，密钥由 Microsoft 管理。

每个组织相互独立

  • 数据库中的每条记录都属于一个组织，PostgreSQL 行级安全确保 E1 只能读取您当前所在组织的行。
  • 每次构建都会通过自动化测试检查每张表的隔离性。

专用网络

  • 数据库没有公网地址：只有 E1 服务器能在 Azure 专用网络内访问它。
  • 文件无法从互联网打开，存储密钥已关闭：仅通过身份进行访问。

机密与密钥

  • 所有机密都保存在 Azure Key Vault 中，并受到防删除保护。E1 服务器使用其自身的 Azure 身份读取它们。
  • AI 服务无需 API 密钥：E1 以自身身份登录该服务，因此不会有密钥泄露。
  • 日志中绝不包含密码、令牌或密钥。

受保护的应用

  • 严格的内容安全策略（Content Security Policy），并防范跨站请求和框架嵌入。
  • 限制登录及其他操作的尝试频率。
  • 无论由谁或什么发起，E1 服务器都会检查每一项更改的权限。

安全发布

  • macOS 应用由 Apple 签名并公证，Windows 应用使用 Azure Artifact Signing 签名。更新绝不会回退到旧版本。
  • 每次构建都会扫描泄露的机密和已知漏洞，并附带软件物料清单。
  • 发布版本只有经人工批准后才会进入 E1 Cloud。

审计日志

  • 登录、失败的登录、成员、邀请、许可、角色、导出和通行密钥都会被记录。管理员可在“组织 → 审计”下查看。
  • 每次调用 AI 都会记录其模型和大小，但不记录您消息的文本。

AI 由您掌控

  • 您的组织可将 Alex 设置为开启、仅回答或关闭。
  • Alex 以您的权限工作，绝不越权。受限数值会在发送给模型之前被移除。
  • Alex 在一次删除超过 10 个对象之前会先征求您的确认。

备份与恢复

不会丢失任何内容。

您的数据始终在备份，保存在多个位置，而且您可以随时将其全部导出。

数据库，恢复到任意时间点7 天
已删除或被覆盖的文件14 天
Key Vault 中的密钥和机密90 天

数据库

  • 由 Azure Database for PostgreSQL 进行持续备份：数据库可恢复到最近 7 天内的任意一分钟。
  • 备份还会复制到 Azure 在欧盟的配对区域，因此即使整个区域失效也能保留。

文件和文档

  • 每个文件存储三份，分别位于该区域内三个独立的数据中心（区域冗余存储）。
  • 每个文件的早期版本都会保留，已删除的文件可在 14 天内恢复。
  • 已发布的修订版永远不会被删除。

恢复目标

  • 最多可能丢失的工作量1 小时（RPO）
  • 恢复服务所需时间8 小时（RTO）

E1 的每次构建都会自动测试从备份恢复。

申请恢复

误删了内容？大多数更改可直接在 E1 中通过对象或图纸的历史记录撤销。如需更多恢复，请由您组织的所有者或管理员发送邮件至 support@lanxtor.com，并注明需要回退到的时间。我们可以将数据库恢复到最近 7 天内的任意时间点，并恢复最近 14 天内删除的文件。

带走您的全部数据

所有者和管理员可随时在“组织 → 导出全部”下导出整个组织：一个归档文件，包含以开放 JSON lines 格式导出的每张表及每个文件，最大 4 GB。导出绝不会因存储空间不足而被拒绝，并会记录在审计日志中。

试用结束后，组织将变为只读：所有内容仍然可见，并且仍可导出。

问题

安全团队常问的问题。

LANXTOR 员工能打开我的图纸吗？

不能。LANXTOR 支持团队可以看到您的帐户和账单数据，以便协助处理许可和席位。数据库不会向支持团队开放您的项目、对象、图纸或文档，支持团队所做的每一项更改都会显示在您的审计日志中。

我的数据会离开欧盟吗？

您的项目、文件和备份保留在欧盟境内的 Azure 数据中心。Alex 的默认模型 GPT-4.1 运行在欧盟的瑞典中部区域。只有当 Editor 在聊天中选择 Claude Opus 5.5 时，这些请求才可能在欧盟境外处理。您的组织可以关闭 Alex。

如果某个 Azure 数据中心发生故障怎么办？

文件存储在该区域内三个独立的数据中心，因此其中一个失效不会影响它们。数据库备份还会复制到 Azure 在欧盟的配对区域。我们的目标是在 8 小时内恢复服务，最多丢失 1 小时的工作。

如果我们不再使用，如何取出数据？

所有者或管理员可随时在“组织 → 导出全部”下以开放格式导出整个组织：数据为 JSON lines，文件为原始文件。之后可发送邮件至 support@lanxtor.com 请我们删除该组织。

我们可以选择其他区域或自己的云吗？

E1 Cloud 即将推出美国区域。如果您的数据必须存放在特定位置或遵循您自己的规则，可将 E1 作为企业版安装运行在 Microsoft Azure、Amazon Web Services、Google Cloud、Alibaba Cloud（即将推出，面向中国大陆）或您自己的服务器上，并使用您自己的 PostgreSQL 数据库。

可以使用单点登录吗？

可以。您的人员可通过 OpenID Connect（Okta、Microsoft Entra ID、Google Workspace、Keycloak、ADFS 等）使用贵公司自己的登录方式登录，也可以设为仅允许这种方式，适用于我们已为您的组织验证的电子邮件域。您的目录可通过 SCIM 2.0 创建、更新和停用成员、组和许可。所有者和管理员可在“组织 → 登录”下进行设置。SAML 2.0 暂不可用；如有需要，请联系销售。
