数据库

数据库决定 E1 的速度。

应选择什么

  • 数据库PostgreSQL 16
  • 在 Microsoft Azure 上Azure Database for PostgreSQL – Flexible Server，General Purpose（试用用 D2ds_v6，最多 50 名工程师用 D4ds_v6）
  • 在您自己的服务器上专用核心，以及本地 SSD 或满足上述 IOPS 的 SAN
  • 连接数E1 至少需要 300 个：每台 E1 服务器打开 41 个
  • 备用位于另一可用区的副本，可自动接管，用于日常工作
  • 备份时间点恢复，保留 35 天

不应选择什么

  • 可突增或共享核心数据库（Azure Burstable B 系列等）：一旦 CPU 积分用完，其速度会降到一个核心的一小部分，E1 每次点击都要等待数秒。
  • 小而慢的磁盘：32 GB 磁盘仅提供 120 IOPS，对同时工作的工程师来说太少。
  • 远离 E1 服务器的数据库：位于另一区域或数据中心，会使每次点击的每一步都增加延迟。
  • 与其他应用共享的数据库：它们的负载会变成您的工程师的等待时间。

  • 登录通过 OpenID Connect 使用您自己的登录
问题

IT 团队常问的问题。

我们可以从小规模开始，以后再扩展吗？

可以。从适合当前同时工作人数的那一行开始。托管数据库只需更改一项设置并重启几分钟即可升级到更大规格，E1 服务器会在负载下自动增加。只有试用规格不适合日常工作。

为什么不用更便宜的可突增数据库？

可突增数据库只有在拥有 CPU 积分时才快。工程师一次工作数小时，积分会耗尽，数据库随即降到一个核心的一小部分：此后每次点击都要等待数秒。省下的钱会因工程师的等待而成倍损失。

你们会在我们开始前核查规格吗？

会。请告诉我们将有多少工程师同时工作以及项目规模，我们会确认或调整规格。对于超过 200 名工程师同时工作的情况，我们会根据负载测试确定安装规格。请联系销售。
