用于方案和改造的分支。

在 E1 中，分支是项目部分设计的工作副本。工程师在分支中进行更改，而主线保持不变；逐值拉取主线的更改，在数据和图纸上解决冲突，并将分支作为一项可整体撤销的更改推送回主线。分支可用于假设分析、设计变更、改造包和调试范围。

分支

更改部分设计，主线保持不变

在 E1 中，分支包含装置模型中选定的范围；您在其中所做的更改只改变分支，而不改变项目的主线设计。

可以从项目的“分支”页面、项目的右键菜单启动分支，或在资源管理器或 2D 空间中选择对象，然后选择“分支 ▸ 新建分支…”。范围预览会列出您的选择所带入的内容及原因：一台泵会将其管口、相连管线和绘制它的 2D 空间作为“可编辑”带入，将其所属对象作为“信息”带入。在未锁定的行上，可将其改为“排除”或“信息”，然后创建分支。

进入分支后，整个项目显示分支的内容，并有一个提示条说明您正处于分支中。分支图标标记它所更改的每个对象和 2D 空间。分支以外的对象显示为灰色，在分支中不能更改。在图纸上，“显示主线”会以粉色将主线的当前版本叠加在上方，让您准确看到分支绘制的不同之处；“此图纸上的分支”会以各自的颜色显示所有更改该 2D 空间的未关闭分支。

有些内容始终属于主线：发布修订、项目设置和库在分支中会被拒绝。位号统一分配，因此两个分支永远不会使用同一个编号。分支永远不会扩大您在主线中可更改的范围。

冲突

从主线拉取并逐值解决冲突

在 E1 中，“从主线拉取”将主线的更改逐值带入分支；只有双方更改不同的内容才是冲突。

当有人在分支范围内更改主线时，分支卡片上的铃铛会响起，并列出更改了什么以及由谁更改。“从主线拉取”会带入主线更改而分支未更改的所有内容。双方更改不同的数值列在“冲突”下，按对象分组，并排显示基准、主线和分支：选择“保留我的”、“采用对方的”，或输入一个值并点击“使用该值”。“全部保留我的”和“全部采用对方的”可一次解决多个冲突。

冲突也会在图纸上解决。两侧都移动过的符号会显示两次：Main 为蓝色，Branch 为橙色，并以虚线相连，单击要保留的那个即可。状态遵循同样的规则：若 main 和分支都更改了某个状态，E1 会建议取较低的状态；分支中给出的签署，在该分支此后发生更改时即告失效。

审查

合并到 main 前审核：分支类型与合并请求

在 E1 中，每个分支都有一个类型，用于规定它在合并到 main 之前是否需要审核，以及如何处理其冲突和 main 中的编辑。

每个项目开始时都有三种分支类型：Working branch、Design change (reviewed) 和 Commissioning package。项目管理员（Project administrator）为每种类型设置：Review before main、Four eyes、After push 之后的处理方式、Editing in main 如何对待该分支的对象（Mark、Warn 或 Block），以及图形冲突的规则。位号或校验冲突始终由人来决定。

需要审核的分支通过 Ask for review 发起审核。审核人在其 Inbox 中看到合并请求，期间相关对象显示为 Under merge review。由 Lead engineer 批准，或单击 Request changes… 并说明需要修改的内容；启用四眼原则时，作者不能批准自己的分支。Alex 从不批准或驳回合并请求，这始终由人来完成。

对于执行变更管理（MOC）流程的工厂，经审核的分支会将每项修改与正式设计分开保存，直到第二位工程师批准为止，并留下一份记录其所有更改的协议。MOC 程序本身仍由贵公司自行制定。

推送

作为一次更改推送到 main，并留有协议

在 E1 中，Push to main 将分支作为一次更改并入项目，每次推送都会留下一份记录其更改内容的协议。

由 Lead engineer 或更高角色执行推送，且其角色必须允许分支中的每一项更改。若 main 中有尚未拉取、且位于分支范围内的更改，或仍有未解决的冲突，或所需审核尚未批准，E1 将拒绝推送，因此 main 中的任何内容都不会在无人察觉的情况下被覆盖。推送作为一次更改 Pushed branch… 记入 main 的历史，Undo this change 可将其全部撤销。

每次推送分支或调试包都会生成一份推送协议：包括日期、推送人，以及其创建、更改或删除的每个对象，并列出每个字段更改前后的值。协议由推送本身生成，永不更改。推送后，分支保持打开并以已推送的内容为基准，或按其类型的规定关闭。

调试

从分支中划分出调试包

在 E1 中，分支中已完成的部分可成为调试包，单独合并到 main，每个包都有自己的日期、负责人和说明。

在分支卡片上，New commissioning package 用于创建调试包。在分支内，用 Package boundary（套索、矩形或椭圆）在图纸上圈出工作范围并添加，或右键单击对象并选择 Branch ▸ Add to commissioning package。离开边界的管道会在其穿越边界处标出，调试包会列出它仍需要的内容，例如分支创建的某个区域。

为调试包填写说明、优先级、计划调试日期、调试负责人和验收人。Mark ready 会按当前状态将其从分支中划出，随后单独审核并推送到 main。之后，分支对这些对象以 main 为基准，因此下次拉取不会产生冲突，推送时也不会重复这些对象。所含装置完成调试后，设置 Commissioned on。分支和调试包是库类 Branch 和 Commissioning package 的对象，因此可带有您自己的属性，并出现在查询中。

监管

仪表板上的分支，以及分支中的 Alex

在 E1 中，Branches 仪表板和每个对象的 Branches 选项卡显示了哪些内容正在何处被更改。

Dashboards → Branches 显示打开的分支、审核中的分支、其平均存续时间、未解决的冲突，以及按状态和所有者统计的分支。对象的 Branches 选项卡列出可能更改该对象的打开分支，以及每个分支到目前为止的更改。所有者、所有者组和指派人明确了每个分支由谁负责，Access and sharing 可将分支限制为仅应看到它的人可见。

在分支中，Alex 和已存储的助手只更改该分支，从不更改 main，且只更改您有权更改的内容。Alex 提议的更改可通过 Open as branch 保留为分支，以便在任何内容进入正式设计之前先进行审核。

问题

工程师常问的问题。

E1 中的分支是什么？

项目设计中某一部分的工作副本。您在其中进行更改，而 main 保持不变；您可以拉入 main 的更改，并在准备就绪时将其作为一次更改推送回 main。

分支可以用来做什么？

假设情景分析、需要审核的设计变更、改造包和调试范围。每个项目开始时都有分支类型 Working branch、Design change (reviewed) 和 Commissioning package。

如果 main 和分支更改了同一个值，会怎样？

Pull from main 会将其列为冲突，并排显示 Base、Main 和 Branch。您可以选择 Keep mine、Take theirs 或输入一个值。两侧都移动过的符号会在图纸上显示两次，您可以单击要保留的那个。

谁可以将分支推送到 main？

Lead engineer 或更高角色，且其角色允许分支中的每一项更改。若 main 在其范围内有未拉取的更改、仍有未解决的冲突，或所需审核尚未批准，推送将被拒绝。

推送可以撤销吗？

可以。推送作为一次更改记入 main 的历史，Undo this change 可将其全部撤销。其推送协议保存了它做出的每一项更改，以及每个字段更改前后的值。

可以在分支中发布修订吗？

不可以。发布修订、项目设置和库都在 main 中更改。请先推送分支，然后在 main 中发布修订。

什么是调试包？

分支中通过圈选或右键单击收集起来的一部分，带有日期、负责人和说明。标记为就绪并通过审核后，它会单独推送到 main。
