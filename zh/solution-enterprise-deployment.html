部署位置

默认在云端，政策要求时部署在您自己的服务器上

E1 可在三个位置运行：由 LANXTOR 运营的 E1 Cloud；您自己的 Microsoft Azure 订阅；或您自己数据中心的本地部署。各处运行的都是同样的 E1。

大多数团队从 LANXTOR 在欧盟托管的 E1 Cloud 开始。当合同、出口管制规定或公司政策规定了工程数据必须存放的位置时，企业安装可将数据放在那里：在您自己的订阅、区域和网络中实现数据主权。Amazon Web Services、Google Cloud 和 Alibaba Cloud 即将作为更多选择推出。

在您自己的 Azure 中有两种运行方式：由您的 IT 部门按照 LANXTOR 的说明安装和运行，或由 LANXTOR 在您的 Azure 中为您运行。无论哪种方式，订阅、数据和 Azure 账单都归您所有。

E1 的状态栏始终显示项目的存放位置，例如 Microsoft Azure，或 PostgreSQL 加上您的数据库服务器名称，让每个人都清楚自己所在的是哪个安装。

安装

安装如何设置

在 E1 中，LANXTOR 为您的组织开通后，组织的 Owner 和 Administrator 可在 E1 Cloud 的“账户”中的“自有安装”下，下载安装 E1 所需的一切。

安装包是一个 zip 文件：包含 E1 的最新版本、您访问 E1 发布版本的权限以及一份简短的“从这里开始”。您的 IT 部门在 Azure Cloud Shell 中解压并按照安装步骤操作；您自己的 E1 会在您的订阅中创建并输出其地址。每次下载都会要求您用通行密钥确认身份，并记录在组织的审计日志中。

新安装没有所有者。只有电子邮件地址被指定为其运营者的人，才能通过首先登录来认领它；其他任何人都不能。桌面应用通过地址连接到您的安装，用户在浏览器中使用它的方式与 E1 Cloud 相同。

许可证

签名的许可证文件，离线校验

在您自己的安装中，方案、各类许可证的席位、内容包和日期均来自 LANXTOR 签名的许可证文件。E1 会自行离线校验。

Owner 从 E1 Cloud 的“账户 → 自有安装”下载许可证文件，并在“文件 → 组织… → 成员”中加载一次；每当 LANXTOR 签发续期文件时再次加载。方案和席位立即生效，加载操作记录在审计日志中。文件与您安装的地址绑定。E1 会拒绝签名后被修改的文件、用于其他地址的文件以及尚未生效的文件，并说明原因。

许可证到期前三十天，每位 Owner 和 Administrator 都会在收件箱中收到通知。到期后有一段宽限期，除非您的合同另有规定，否则为 30 天，期间一切照常运行。宽限期过后，安装变为只读，直到加载续期文件为止：每个人仍可打开、查看和导出所有内容。E1 绝不会被锁定。

登录

公司单点登录和目录同步

在 E1 中，同事可通过任何 OpenID Connect 提供商使用公司账户登录，您的公司目录通过 SCIM 2.0 在 E1 中创建、更新和停用他们。

Owner 和 Administrator 与您的 IT 部门一起在“文件 → 组织… → 登录”下设置登录，例如使用 Okta、Microsoft Entra ID、Google Workspace、Keycloak 或 ADFS。登录适用于您公司已验证的电子邮件域名，“仅限此方式”会使其成为这些用户唯一的登录途径。也可以使用公司 Microsoft 账户登录。

目录同步会停用离职人员：其成员资格、许可证和角色终止，无法再登录，但其历史记录保留。目录组成为 E1 组，组可以授予许可证，例如 E1-Editors → Editor。Owner 和 Administrator 仍需用通行密钥确认。

控制

按您的规则进行审计、访问和集成

在 E1 中，管理员可以看到谁做了什么：“审计”选项卡列出重要事件以及发送给 AI 模型的每个请求，访问历史显示成员、许可证、组和角色的每次变更及其前后状态。

E1 支持人员无权访问您的数据。当其为支持工单申请访问权限时，在 Owner 或 Administrator 批准前不会授予任何权限；批准的期限为几个小时，可为只读或允许修改；点击“结束”即可立即终止。支持人员的一切操作都会显示在历史记录和审计日志中。

其他系统可通过 E1 的 API（使用访问令牌和服务账户）、签名的 webhook 和变更源，或通过 MQTT、AMQP 和 Kafka 消息代理进行连接。在您自己的安装中，消息代理可以位于您自己的网络内。Owner 和 Administrator 可随时以开放格式导出整个组织。

  • 数据：您自己的 PostgreSQL 数据库，位于您的订阅或数据中心。
  • 更新：在您选择的时段自动安装；紧急修复在 1 小时内送达。
  • 授权：单点登录，多种许可证，一张发票。
  • 退出：“导出全部”以 JSON lines 格式提供每张表以及所有文件。
问题

工程师常问的问题。

E1 能本地部署吗？

可以。除 E1 Cloud 和您自己的 Microsoft Azure 外，E1 还可以本地部署在您自己的服务器上，使用您自己的 PostgreSQL 数据库。请联系销售进行规划。

我们可以在哪些云中安装 E1？

目前支持 Microsoft Azure。Amazon Web Services、Google Cloud 和 Alibaba Cloud 即将推出。

在自有安装中，LANXTOR 会持有我们的数据吗？

不会。在您自己的 Azure 中，无论由您的 IT 部门运行 E1，还是由 LANXTOR 在其中为您运行，订阅、数据和账单都归您所有。只有在 Owner 或 Administrator 批准支持请求后，E1 支持人员才能看到您的项目。

E1 需要联系 LANXTOR 来校验许可证吗？

不需要。许可证文件由 LANXTOR 签名，由 E1 自行离线校验。LANXTOR 签发续期文件时，您加载即可。

如果我们的许可证文件到期会怎样？

随后有一段宽限期，除非您的合同另有规定，否则为 30 天，期间一切照常运行。宽限期过后，安装变为只读：所有内容都可以打开、查看和导出，但不能修改，直到 Owner 加载续期文件为止。

支持哪些登录提供商？

任何 OpenID Connect 提供商，例如 Okta、Microsoft Entra ID、Google Workspace、Keycloak 或 ADFS，并支持 SCIM 2.0 目录同步。公司 Microsoft 账户同样可用。

更新如何安装？

更新会在您选择的时段自动安装，紧急修复在 1 小时内安装。服务器更新后，浏览器和桌面应用中的 E1 会提示每位用户新版本已就绪。
