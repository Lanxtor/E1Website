Where

Cloud by default, your own servers when policy requires

E1 runs in three places: in E1 Cloud, run by LANXTOR; in your own Microsoft Azure subscription; or on-premises in your own data centre. It is the same E1 in each.

Most teams start in E1 Cloud, hosted by LANXTOR in the EU. When contracts, export rules or company policy say where engineering data must be kept, an enterprise installation puts it there: data sovereignty in your own subscription, region and network. Amazon Web Services, Google Cloud and Alibaba Cloud are coming as further choices.

In your own Azure there are two ways to run it. Your IT installs and runs it with LANXTOR's instructions, or LANXTOR runs it in your Azure for you. Either way, the subscription, the data and the Azure bill are yours.

The status bar in E1 always names where the projects are kept, for example Microsoft Azure or PostgreSQL with the name of your database server, so everyone can see which installation they are in.

Install

How an installation is set up

In E1, the Owners and Administrators of your organization download everything to install E1 from their Account in E1 Cloud, under Own installation, once LANXTOR has turned it on for the organization.

The installation package is one zip: the newest release of E1, your access to E1's releases and a short Start here. Your IT unzips it in Azure Cloud Shell and follows the install steps; your own E1 is created in your subscription and prints its address. Each download asks you to confirm it is you with a passkey, and is recorded in your organization's audit log.

A new installation has no owner. Only the person whose email address was named as its operator can claim it by signing in first; nobody else can. The desktop app connects to your installation by its address, and people use it in the browser as they would E1 Cloud.

License

A signed license file, checked offline

In your own installation, the plan, the seats of each license, the content packages and the dates come from a license file signed by LANXTOR. E1 checks it on its own, offline.

The Owner downloads the license file from Account → Own installation in E1 Cloud and loads it once in File → Organization… → Members, and again each time LANXTOR issues a renewed one. The plan and seats apply at once, and loading it is in the audit log. A file is bound to your installation's address. E1 refuses a file that was changed after signing, a file for another address and one that is not valid yet, and says why.

Thirty days before a license ends, every Owner and Administrator gets a notice in the Inbox. After the end comes a grace period, 30 days unless your contract says otherwise, in which everything still works. After that the installation is read-only until a renewed file is loaded: everyone can still open, view and export everything. E1 is never locked.

Sign-on

Company single sign-on and directory sync

In E1, colleagues sign in with their company account through any OpenID Connect provider, and your company directory creates, updates and deactivates them in E1 with SCIM 2.0.

Owners and Administrators set up sign-on under File → Organization… → Sign-on with your IT, for example with Okta, Microsoft Entra ID, Google Workspace, Keycloak or ADFS. Sign-on works for your company's verified email domains, and Only this way makes it the one way in for them. Signing in with a company Microsoft account is also available.

Directory sync deactivates whoever leaves: their membership, license and roles end and they can no longer sign in, while their history stays. Directory groups become E1 groups, and a group can give a license, for example E1-Editors → Editor. Owners and Administrators still confirm with a passkey.

Control

Audit, access and integration under your rules

In E1, administrators see who did what: the Audit tab lists important events and every request sent to an AI model, and access history shows every change to members, licenses, groups and roles with before and after.

E1 support has no access to your data. When it asks for access for a support case, nothing is given until an Owner or Administrator approves it, for a few hours, read-only or with changes; it ends at once with End. Everything support does shows in history and the audit log.

Other systems connect through E1's API with access tokens and service accounts, through signed webhooks and a change feed, or through MQTT, AMQP and Kafka brokers. On your own installation a broker may be in your own network. Owners and Administrators can export the whole organization at any time, in open formats.

Questions

Questions engineers ask.

Can E1 run on-premises?

Yes. Besides E1 Cloud and your own Microsoft Azure, E1 can be installed on-premises on your own servers, with your own PostgreSQL database. Contact sales to plan it.

Which clouds can we install E1 in?

Microsoft Azure today. Amazon Web Services, Google Cloud and Alibaba Cloud are coming.

Does LANXTOR hold our data in an own installation?

No. In your own Azure the subscription, the data and the bill are yours, whether your IT runs E1 or LANXTOR runs it there for you. E1 support sees your projects only if an Owner or Administrator approves a support request.

Does E1 need to call LANXTOR to check the license?

No. The license file is signed by LANXTOR and checked by E1 itself, offline. You load a renewed file when LANXTOR issues one.

What happens if our license file runs out?

A grace period follows, 30 days unless your contract says otherwise, in which everything works. After it the installation is read-only: everything can be opened, viewed and exported, but not changed, until the Owner loads a renewed file.

Which sign-in providers work?

Any OpenID Connect provider, such as Okta, Microsoft Entra ID, Google Workspace, Keycloak or ADFS, with SCIM 2.0 directory sync. Company Microsoft accounts work too.

How are updates installed?

Updates install themselves in the hour you choose, and urgent fixes within the hour. When your server is updated, E1 in the browser and in the desktop app tells each user that a new version is ready.
