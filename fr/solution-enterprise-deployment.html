Vos données, votre déploiement : E1 dans votre propre cloud ou centre de données.

E1 fonctionne par défaut comme un service cloud, et comme une installation d'entreprise lorsque votre politique l'exige. LANXTOR vous fournit l'installation : le même E1, avec vos projets, dessins et documents dans votre propre abonnement Microsoft Azure ou sur site sur vos propres serveurs, dans votre propre base de données PostgreSQL, selon vos propres règles. Les mises à jour s'installent d'elles-mêmes à l'heure que vous choisissez.

Où

Cloud par défaut, vos propres serveurs quand la politique l'exige

E1 fonctionne à trois endroits : dans E1 Cloud, géré par LANXTOR ; dans votre propre abonnement Microsoft Azure ; ou sur site dans votre propre centre de données. C'est le même E1 partout.

La plupart des équipes commencent dans E1 Cloud, hébergé par LANXTOR dans l'UE. Lorsque des contrats, des règles d'exportation ou la politique de l'entreprise imposent où les données d'ingénierie doivent être conservées, une installation d'entreprise les y place : souveraineté des données dans votre propre abonnement, région et réseau. Amazon Web Services, Google Cloud et Alibaba Cloud arrivent comme autres choix.

Dans votre propre Azure, il y a deux façons de l'exploiter. Votre service informatique l'installe et l'exploite avec les instructions de LANXTOR, ou LANXTOR l'exploite dans votre Azure pour vous. Dans les deux cas, l'abonnement, les données et la facture Azure sont les vôtres.

La barre d'état d'E1 indique toujours où sont conservés les projets, par exemple Microsoft Azure ou PostgreSQL avec le nom de votre serveur de base de données, pour que chacun voie dans quelle installation il se trouve.

Installation

Comment une installation est mise en place

Dans E1, les Owners et Administrators de votre organisation téléchargent tout ce qu'il faut pour installer E1 depuis leur Account dans E1 Cloud, sous Own installation, une fois que LANXTOR l'a activé pour l'organisation.

Le paquet d'installation est un seul zip : la dernière version d'E1, votre accès aux versions d'E1 et un court Start here. Votre service informatique le décompresse dans Azure Cloud Shell et suit les étapes d'installation ; votre propre E1 est créé dans votre abonnement et affiche son adresse. Chaque téléchargement demande de confirmer que c'est bien vous avec une clé d'accès (passkey), et est enregistré dans le journal d'audit de votre organisation.

Une nouvelle installation n'a pas de propriétaire. Seule la personne dont l'adresse e-mail a été désignée comme son exploitant peut la revendiquer en se connectant la première ; personne d'autre ne le peut. L'application de bureau se connecte à votre installation par son adresse, et les utilisateurs l'emploient dans le navigateur comme ils le feraient avec E1 Cloud.

Licence

Un fichier de licence signé, vérifié hors ligne

Dans votre propre installation, la formule, les postes de chaque licence, les packs de contenu et les dates proviennent d'un fichier de licence signé par LANXTOR. E1 le vérifie de lui-même, hors ligne.

L'Owner télécharge le fichier de licence depuis Account → Own installation dans E1 Cloud et le charge une fois dans File → Organization… → Members, puis à nouveau chaque fois que LANXTOR en émet un renouvelé. La formule et les postes s'appliquent aussitôt, et le chargement figure dans le journal d'audit. Un fichier est lié à l'adresse de votre installation. E1 refuse un fichier modifié après signature, un fichier destiné à une autre adresse et un fichier qui n'est pas encore valide, et en indique la raison.

Trente jours avant la fin d'une licence, chaque Owner et Administrator reçoit une notification dans l'Inbox. Après la fin vient un délai de grâce, de 30 jours sauf disposition contraire de votre contrat, pendant lequel tout fonctionne encore. Ensuite, l'installation est en lecture seule jusqu'au chargement d'un fichier renouvelé : chacun peut toujours tout ouvrir, consulter et exporter. E1 n'est jamais verrouillé.

Authentification

Authentification unique de l'entreprise et synchronisation de l'annuaire

Dans E1, les collègues se connectent avec leur compte d'entreprise via n'importe quel fournisseur OpenID Connect, et l'annuaire de votre entreprise les crée, les met à jour et les désactive dans E1 avec SCIM 2.0.

Les Owners et Administrators configurent l'authentification sous File → Organization… → Sign-on avec votre service informatique, par exemple avec Okta, Microsoft Entra ID, Google Workspace, Keycloak ou ADFS. L'authentification fonctionne pour les domaines de messagerie vérifiés de votre entreprise, et Only this way en fait le seul accès pour eux. La connexion avec un compte Microsoft d'entreprise est également disponible.

La synchronisation de l'annuaire désactive toute personne qui part : son appartenance, sa licence et ses rôles prennent fin et elle ne peut plus se connecter, tandis que son historique reste. Les groupes de l'annuaire deviennent des groupes E1, et un groupe peut donner une licence, par exemple E1-Editors → Editor. Les Owners et Administrators confirment toujours avec une clé d'accès (passkey).

Maîtrise

Audit, accès et intégration selon vos règles

Dans E1, les administrateurs voient qui a fait quoi : l'onglet Audit liste les événements importants et chaque requête envoyée à un modèle d'IA, et l'historique des accès montre chaque modification des membres, licences, groupes et rôles avec l'avant et l'après.

Le support E1 n'a aucun accès à vos données. Lorsqu'il demande un accès pour un cas de support, rien n'est accordé tant qu'un Owner ou un Administrator ne l'approuve pas, pour quelques heures, en lecture seule ou avec modifications ; il prend fin aussitôt avec End. Tout ce que fait le support apparaît dans l'historique et le journal d'audit.

D'autres systèmes se connectent par l'API d'E1 avec des jetons d'accès et des comptes de service, par des webhooks signés et un flux de modifications, ou par des brokers MQTT, AMQP et Kafka. Sur votre propre installation, un broker peut se trouver dans votre propre réseau. Les Owners et Administrators peuvent exporter à tout moment toute l'organisation, dans des formats ouverts.

  • Données : votre propre base de données PostgreSQL, dans votre abonnement ou centre de données.
  • Mises à jour : elles s'installent d'elles-mêmes à l'heure que vous choisissez ; correctifs urgents en moins d'une heure.
  • Licences : une authentification unique, de nombreuses licences, une seule facture.
  • Sortie : Export everything fournit chaque table en lignes JSON et chaque fichier.
Questions

Les questions que posent les ingénieurs.

E1 peut-il fonctionner sur site ?

Oui. Outre E1 Cloud et votre propre Microsoft Azure, E1 peut être installé sur site sur vos propres serveurs, avec votre propre base de données PostgreSQL. Contactez les ventes pour le planifier.

Dans quels clouds pouvons-nous installer E1 ?

Microsoft Azure aujourd'hui. Amazon Web Services, Google Cloud et Alibaba Cloud arrivent bientôt.

LANXTOR détient-il nos données dans une installation propre ?

Non. Dans votre propre Azure, l'abonnement, les données et la facture sont les vôtres, que votre service informatique exploite E1 ou que LANXTOR l'y exploite pour vous. Le support E1 ne voit vos projets que si un Owner ou un Administrator approuve une demande de support.

E1 doit-il appeler LANXTOR pour vérifier la licence ?

Non. Le fichier de licence est signé par LANXTOR et vérifié par E1 lui-même, hors ligne. Vous chargez un fichier renouvelé quand LANXTOR en émet un.

Que se passe-t-il quand notre fichier de licence arrive à expiration ?

Un délai de grâce suit, de 30 jours sauf disposition contraire de votre contrat, pendant lequel tout fonctionne. Après cela, l'installation est en lecture seule : tout peut être ouvert, consulté et exporté, mais pas modifié, jusqu'à ce que l'Owner charge un fichier renouvelé.

Quels fournisseurs de connexion fonctionnent ?

Tout fournisseur OpenID Connect, comme Okta, Microsoft Entra ID, Google Workspace, Keycloak ou ADFS, avec synchronisation d'annuaire SCIM 2.0. Les comptes Microsoft d'entreprise fonctionnent aussi.

Comment les mises à jour sont-elles installées ?

Les mises à jour s'installent d'elles-mêmes à l'heure que vous choisissez, et les correctifs urgents en moins d'une heure. Quand votre serveur est mis à jour, E1 dans le navigateur et dans l'application de bureau indique à chaque utilisateur qu'une nouvelle version est prête.
