About this guide

This guide covers the shared set-up of E1: the Configuration place with its object classes, attributes, shapes and relationships, the company library where your organization adds its own classes and attributes, catalogs of approved products, the content packages a project uses, and the project settings. A change made here applies to everyone, not only to you; your own preferences are in Settings.

The typical workflow

  1. Open the place and find your way around its sections: The Configuration place.
  2. Look up what E1 already knows: Object classes, Attributes and pick lists, Shapes, Relationships.
  3. See which content packages bring that content and which ones your project uses: Content packages and Project settings.
  4. Add your company's own attributes and classes, publish them and keep projects up to date: Company library, Updates available, Upgrade with preview, This project only, Convention templates, Pin a library version.
  5. Keep approved products in catalogs and make objects from them: Catalogs, From catalog, Re-apply and Detach, Catalog import.
  6. The other sections in brief: Alex knowledge, Datasheets, Project defaults, Cloud AI model, Storage.
  7. What comes next: Rules, Units of measurement, Switching packages on and off and Package licensing and updates.

Before you start

  • You are signed in and a project is open (the company library and the catalogs are kept on the server for every project of the organization, so they need an open project).
  • Anyone may look at the Configuration place. Changing the company library needs the organization role Owner or Library administrator; catalogs also Catalog maintainer; project settings, the project library and project catalogs need the project role Project administrator. An Owner or Project administrator who signed in without a passkey acts with less rights until they add one under Account → Passkeys.

There is no screen yet to give someone an organization role such as Library administrator or Catalog maintainer; an invitation makes a person a Member. Ask your E1 contact to set the role for testing.

The Configuration place

AvailableUpdated 2026-11-06LIB-configuration

Configuration is where the shared set-up of E1 lives: the data model, the company library, catalogs, Alex's knowledge, content packages, project settings and the installation. A change here applies to everyone. The place remembers the section and item you left it on.

Where
The left rail → Configuration (the sliders icon near the bottom)
Who
Everyone may look; changes need the rights named in each section
Before you start
E1 is open and you are signed in.

Steps

#ActionExpected result
1Click Configuration in the left rail.A tab Configuration opens. The heading reads "Shared: a change here applies to everyone. Your own preferences are in Settings."
2Look at the section bar along the top.The sections are, in groups: Object classes, Attributes, Shapes, Relationships, Company library, Catalogs; Alex knowledge, Rules (with an M6 badge); Content and standards, Datasheets; Project defaults, Project settings; Cloud AI model, Storage. Several show a count (for example Object classes 2014).
3Click Attributes, then close the tab and click Configuration in the rail again.The place opens on Attributes, the section you left it on.

The buttons New class, Add attributes, New group, New subclass, Import from a standard, New attribute, Add to classes, Allow a shape, New shape, Allow for classes, Allow a relationship, New relationship type and Add a content package are placeholders. Your own classes and attributes are made in the Company library. Cloud AI can also open a section for you.

Look up object classes

AvailableUpdated 2026-11-06LIB-object-classes

Object classes lists every kind of object your projects can hold: what attributes it has, which shapes draw it, which relationships it takes part in, and where it may be placed. The list is read only; it shows the classes of the content packages and of your company library.

Where
Configuration → Object classes
Who
Everyone
Before you start
The Configuration place is open.

Steps

#ActionExpected result
1Click Object classes.A class tree opens fully folded (Model Space, Unit Operations, Assets, Systems, …), each folder with the count of concrete classes below it. Above it are the search box "Find a class by name, key or CFIHOS code" and the filters Package, Standard and Kind.
2Expand Assets, Process, Equipment and click Pump.The class detail opens on the right: the parent classes as a breadcrumb, chips (Abstract or Concrete, the package, the standard) and the tabs Attributes, Shapes, Relationships, Subclasses and Behavior.
3Click the Shapes tab.It lists the shapes of this class and the shapes of its subclasses (6 for Pump), the default one marked Default.
4Click the Attributes tab and click Design pressure.The table shows Attribute, Type, Required, Default and From ("Inherited" or "This class"). Clicking the attribute opens the Attributes section on it, with "Used by 2 classes".
5Go back to a class and click the Behavior tab.It shows where objects of the class are placed (Placed in sections, Placed under classes), what they may own, how they are named, what happens when one is deleted, and whether it is in a catalog.
6Set Kind to Abstract (grouping), then click Clear filters.The tree shows only grouping classes; after Clear filters it shows all classes again.

CFIHOS classes also show their CFIHOS facts, such as Synonyms and Tag number format.

Attributes and a project's pick lists

AvailableUpdated 2026-11-06LIB-attributes

Attributes lists every value an object can hold, with its type, unit, range and allowed values, and the classes that use it. The attributes themselves are read only, but a project may give a text or choice attribute its own pick list.

Where
Configuration → Attributes
Who
Everyone may look; editing a project's pick list needs the right to configure the project (Project administrator)
Before you start
A project is open (for the pick list steps).

Steps

#ActionExpected result
1Click Attributes.The groups (CFIHOS, Fluid properties, General, …, Not used by a class) are listed folded with their counts. Above them are the search box and the filters Standard, Category, Type, Package, Use and Pick list.
2Set Pick list to Has a pick list and open an attribute.The detail shows Type, Unit and Allowed values, and a pick list card with the chip "Library list", "Open: other values allowed" or "Closed: only these values", the number of values and a table Value / Description / CFIHOS code. A long list has Find a value and "Show all N values".
3Click Edit the list for your project (on an attribute without a list: Give it a pick list in your project).An editor opens with the choice Its own values or A library pick list.
4Choose Its own values and type one value a line (a description after "|"). For a text attribute, tick "Other values may be typed too" if wanted.The values are shown in the box.
5Click Save.The card's chip reads "project's list" and shows your values.
6Click Back to the library list (or Remove the list).The attribute uses the library list again. Values already set on objects are kept; a value outside a closed list is reported on its object.

With several projects, the Project list chooses the project whose list you edit. Without an open project the card reads "Open a project to configure this list for it."

The company library: drafts, publishing and versions

AvailableSince 2026-11-05Updated 2026-11-08LIB-company-libraryRoadmap 11.1Review checks L1, L2, L3, L4

The company library holds your organization's own attributes, classes and relationship types. A draft changes nothing; once you publish it, every project of the organization has it and E1 checks it like its own. A published version never changes: a new draft becomes the next version.

Where
Configuration → Company library
Who
Saving drafts and publishing for the company: Owner or Library administrator. For This project only: Project administrator.
Before you start
A project is open. Without one the section reads "Open a project first: the company library is kept on the server for every project of the organization."

Steps

#ActionExpected result
1Click Company library.The form shows Library (Company (every project)), New (Attribute), Name, Kind of value and Save draft. Below: "Nothing in the company library yet." (in a new organization).
2Leave New on Attribute. Type the Name "Seal plan", set Kind of value to Choice and type the Choices "API 11, API 53B".The Choices box shows the two values.
3Click Save draft.The table "Company library items" shows Seal plan with Kind Attribute and Draft "Draft". Nothing changes in the projects.
4Click Publish on the row and confirm with OK.The confirmation reads "Publish Seal plan? Every project of the organization gets it, and this version never changes." After OK, the Published column reads "Version 1".
5Set New to Class. Name "Canned motor pump", A kind of Centrifugal pump, Attributes Seal plan (leave Owned under on Assets). Click Save draft, then Publish and OK.The class row reads "Version 1".
6Open Object classes and search "Canned".Canned motor pump is found, under Centrifugal pump, with the attribute Seal plan.
7In the explorer, right-click Assets → New asset… and search "canned".Canned motor pump is offered and can be created.
8Try to create a Canned motor pump under Systems.It is refused with the reason: the class is owned under Assets only.
9Change the class (for example make Seal plan required) and click Save draft.The row shows "Version 1" and a Draft. Projects keep version 1 until version 2 is published.

The other kinds: Attributes for a class (add attributes to an existing class: Class, Attributes) and Relationship type (Inverse name, From, To). An attribute's Kind of value is Text, Whole number, Number, Quantity (with a Unit), Yes / no, Date or Choice. Submit for review marks a draft "In review", but a review is not required: a publisher may publish directly. Withdraw takes a published version back (confirm "Withdraw version n of …?").

An Engineer cannot save or publish (review check L3): the buttons are refused with the reason. An Owner without a passkey acts as a Member and is refused too.

Updates available and Check against projects

AvailableSince 2026-11-05Updated 2026-11-06LIB-library-updatesRoadmap 11.2Review checks L5, L6

When a new version of a company class, attribute, convention template or catalog item is published, the company library lists what in the open project is still on the older version and what changed. Before you publish, Check against projects tells you which objects a draft would break.

Where
Configuration → Company library → the region Updates available in this project (shown only when there is something), and the button Check against projects on a draft
Who
Check against projects: Owner or Library administrator. Anyone may read the updates.
Before you start
A project with objects of a company class (for example the Canned motor pump from Company library), and Pump1 set to Seal plan API 53B.

Steps

#ActionExpected result
1Save a draft of Seal plan whose Choices leave out API 53B.The row shows a Draft.
2Click Check against projects on that row.A report "Checking the draft of …" opens: "1 object would break (of N checked):" naming Pump1 and the reason. With nothing broken it reads "Nothing breaks: N objects in M projects checked."
3Click Close.The report closes; nothing changed in the projects.
4Publish version 2 of a company class that has objects in the project (for example narrow it so it may no longer be owned by Systems).Updates available in this project appears, listing the class with "version 2 · X of Y objects on version 1" and the changes, for example "May no longer be owned by Systems", with Preview upgrade.

The region also lists convention templates ("convention template version 1 → 2 (the project keeps version 1 until you apply it again)" with Apply version 2), catalog items with a newer version (with Re-apply…), withdrawn catalog items still in use, and changed attributes and relationship types ("version a → b").

Updates available is part of the Company library section, not a screen of its own. It reads the newest company classes even for a project pinned to an older library version.

Upgrade objects to a new class version

AvailableSince 2026-11-06LIB-upgradeRoadmap 11.3Review checks L7, L8

Objects stay on the class version they were made with until you upgrade them. Preview upgrade shows, object by object, what would happen; Upgrade applies it as one change you can undo. Values the new version no longer allows are kept as retired values that can only be discarded.

Where
Configuration → Company library → Updates available in this project → Preview upgrade
Who
Lead engineer or above in the project
Before you start
Version 2 of a company class is published and objects of it are on version 1 (see Updates available).

Steps

#ActionExpected result
1Look at the class under Updates available in this project.It reads, for example, "3 of 3 objects on version 1" and "May no longer be owned by Systems".
2Click Preview upgrade.The status reads "Upgrade preview", headed "Upgrading … : what would happen". One line per object: "version 1 → 2 · upgraded", "moved and upgraded", "already current" or "skipped: reason", plus "retired: …" and "defaults: … = …" where they apply. Nothing has changed yet.
3Click Upgrade 2 (the number is the objects that would be upgraded).The result reads, for example, "…: 2 upgraded, 1 skipped". A skipped object stays on version 1.
4Click Close, then Edit → Undo.The whole upgrade goes back in one step: all objects are on version 1 again.
5Upgrade again, then open an upgraded object whose value the new version no longer allows.A note reads "Retired values (version 2 of the class no longer takes them; they can only be discarded):" with the value and Discard.
6Try to type a new value into the retired value; then click Discard.Typing is refused. Discard removes the value and the note.

Convention templates for tag rules

AvailableSince 2026-11-06LIB-convention-templatesRoadmap 11.4Review check L11

A convention template is a published set of tag rules that projects copy in. A project keeps the version it applied until someone applies a newer one, so publishing a new version never retags a project by surprise.

Where
Configuration → Company library (the row with Kind "Convention template") and Updates available in this project
Who
Publishing: Owner or Library administrator. Applying to a project: Project administrator.
Before you start
The project has tag rules (see Tag rules) and Cloud AI is available.

Steps

#ActionExpected result
1Ask Cloud AI to save the project's tag rules as a convention template, then Publish its row in Company library.A row with Kind "Convention template" and "Version 1".
2Click Apply to this project on the row.A confirmation reads "Copy …'s tag rules (version 1) into this project? They replace its rules; existing tags stay until a retag." After OK, the change is held for review before it is applied.
3Publish a new version of the template.Updates available lists "convention template version 1 → 2 (the project keeps version 1 until you apply it again)", with the rules added, removed and changed, and Apply version 2.
4Click Apply version 2.The project's tag rules become version 2; existing tags stay until a retag.

There is no template editor on screen yet: a template is saved through Cloud AI (or an agent), then published in Company library.

Where
Cloud AI (there is no screen for it yet)
Who
The right to configure the project (Project administrator)
Before you start

Steps

#ActionExpected result

2If the project has a relationship of a type the older version lacks, let Cloud AI pin anyway.The pin is refused until that relationship is removed together with it.
3Confirm the pin.The project uses the older version; the pin is recorded as an audit event.

Catalogs of approved products

AvailableSince 2026-11-06Updated 2026-11-08LIB-catalogsRoadmap 20.1, 20.4Review checks L12, L13, L18

A catalog holds the products your organization approves: a pump of a given make and model, with its data and vendor documents. An item is a draft until it is published; a published version never changes, and a new draft becomes the next version. Projects offer published items for new objects.

Where
Configuration → Catalogs
Who
Company catalogs: Owner, Library administrator or Catalog maintainer. Project catalogs: Project administrator. Everyone may read.
Before you start
A project is open. Without one: "Open a project first: the company catalogs are kept on the server for every project of the organization."

Steps

#ActionExpected result
1Click Catalogs.The form New catalog, Description, For (The company (every project)) and Create catalog. With no catalog: "No catalogs yet. Create one to hold approved products."
2Type "Approved pumps" under New catalog and click Create catalog.The catalog is listed with 0 items and opens: "No items in this catalog."
3Click New item. Choose the Class Centrifugal pump, type Manufacturer KSB, Model Etanorm 050, Ordering code ETN050 and the flow rate 50.The editor "New catalog item" shows the class's attributes with their units, Shape ("The class's default") and Vendor documents.
4Click Save draft.The table "Catalog items" shows the item with Status Draft.
5Click Publish and confirm with OK.The confirmation reads "Publish KSB Etanorm 050? This version never changes; projects offer it once their library pin includes it." The item is Published; its view shows version 1 and 50 m³/h.
6Click New version, change the flow rate to 55, click Save draft.The Status reads "Published · draft open".
7Click Publish and OK.The view shows version 2 and "Versions: 1 (date), 2 (date)". Both versions stay.
8Make a second item with the same manufacturer and ordering code; then try a flow rate in kg.Both are refused: "KSB ETN050 is already in the catalog as …", and the unit, because it is not a flow rate ("… \"kg\" is not one of them."). Reinstating a withdrawn item while another has the same manufacturer and ordering code is refused too: "… has the same manufacturer and ordering code; withdraw it first."
9Click Withdraw on an item and OK.The confirmation reads "Withdraw … ? It is no longer offered for new objects; objects made from it keep their values." The item shows Withdrawn; Reinstate brings it back.
10Untick Show drafts and withdrawn.Only published items remain in the table.
11Create a catalog with For This project only, add and publish an item. Open another project's Catalogs.The catalog is listed with "· This project" in its project; the other project does not list it.

An item can carry vendor documents (Title, Link, Kind: Vendor datasheet, Dimension drawing, Manual, Certificate or Other). Create object on a published item makes an object from it ("Made … in … from version n."). Delete catalog is offered only while a catalog has no items. The class of an item is fixed after its first publish.

An Engineer is refused New item, Save draft, Publish and Withdraw with the reason (review check L13). Catalogs can also come with a content package (read only, "· Content package"), but no content package has one yet.

Make an object from a catalog item

AvailableSince 2026-11-06LIB-from-catalogRoadmap 20.2Review checks L14, L15

When you create an object you can start from a published catalog item: the object gets the item's values, and E1 remembers where they came from. A value you change afterwards is marked as differing from the catalog.

Where
Right-click Assets → New asset… → From catalog
Who
Anyone who may create objects; items you are not licensed for are left out
Before you start
A published catalog item for Centrifugal pump (see Catalogs).

Steps

#ActionExpected result
1Right-click Assets → New asset…, search "centrifugal" and choose Centrifugal pump.The dialog "New object in Assets" shows From catalog with "No catalog item" and the published items of the class.
2Choose "KSB Etanorm 050 (ETN050) · v1", type the Name P-CAT and click Create.The pump opens with the note "From catalog: KSB Etanorm 050, v1" above its values. Flow rate, manufacturer, model and ordering code are filled.
3Change the flow rate to 60 and press Enter.The row shows "≠ catalog" (hover shows the catalog's value) and the note adds "· 1 value differs".
4Click Edit → Undo twice.The change, then the pump, are undone.

Later the note tells you when the item moved on: "· version 2 is published", or "· withdrawn from the catalog". In a query, the columns Catalog item, Catalog version (for example "1 (newest 2)") and Catalog state (for example "update available, differs (1)") show this for many objects.

Re-apply a catalog item, or detach from it

AvailableSince 2026-11-06LIB-catalog-reapplyRoadmap 20.3Review checks L16, L17

When a catalog item gets a new version, Re-apply… shows what would change on the objects made from it and writes the new values, keeping the values you changed by hand unless you tick them. Detach ends the link to the catalog and keeps every value.

Where
The object's catalog note → Re-apply… or Detach; or Configuration → Company library → Updates available in this project → Re-apply…
Who
Re-apply: the right to edit attributes. Detach: the right to edit the object.
Before you start
A pump made from a catalog item whose flow rate was changed by hand to 60, and version 2 of the item published.

Steps

#ActionExpected result
1Open the pump and click Re-apply… in its catalog note.The panel "Re-applying …: what would happen" lists "version 1 → 2" and per value "attribute: old → new", and "kept 60 m³/h (changed by hand; the catalog says …)". The box "Overwrite values changed by hand" has a checkbox per value.
2Leave the boxes unticked and click Apply to 1."1 values written on 1 objects". The note shows v2; the flow rate stays 60.
3Click Edit → Undo.The values and "From catalog: …, v1" come back together.
4Click Detach.The catalog note disappears; every value stays.

The panel also reports objects that are skipped (with the reason), values the item no longer has ("the value stays the object's own"), and a changed shape ("placed shapes do not change"). With nothing to change it reads "nothing to change".

Replacing the item by another one has no screen; it goes through Cloud AI, and is refused for an item of another class.

Content packages and standards

AvailableSince 2026-11-02Updated 2026-11-06LIB-content-packagesRoadmap M1.3

Content packages bring the classes, attributes, shapes and relationship types E1 works with, often from a standard. Each project chooses the packages it uses. E1 ships four: Core (always on), Electrical foundation, Plant engineering and CFIHOS.

Where
Configuration → Content and standards; for one project: select it → File → Project settings… → Content packages
Who
Everyone may look; switching packages needs the right to configure the project (Project administrator)
Before you start
E1 is open on the workspace server.

Steps

#ActionExpected result
1Click Content and standards.One card per package: Core 1.4.0, Electrical foundation 1.1.0, Plant engineering 1.3.0 and CFIHOS 2.0.0, each "by e1", with what it brings, counts of Classes, Attributes, Shapes and Relationships, its standards and what it needs (for example "Needs core").
2Click the Classes count on the Plant engineering card.The Object classes section opens.
3Click Choose for a project.The Project settings section opens.
4In the explorer, select the project and choose File → Project settings….A tab "project settings" opens with Content packages: "All content" (Core) marked Always on, and under Disciplines a switch per package with "version · publisher", what it needs, and "not licensed" where that applies.
5Switch off Electrical foundation while Plant engineering is on.A question reads "Switching off Electrical foundation also switches off Plant engineering, which needs it." with Switch off / Cancel. Click Cancel: nothing changes.

The packages

  • Core (always on): projects, documents and sheets, functions, areas, tasks, ports and the off-page connector, the general attributes and first relationship types, the catalog attributes, and the default tag rule template. From 1.4.0, off-page connectors can "continue on" each other.
  • Electrical foundation (needs Core): the motor and its symbol, and cables and wires as objects.
  • Plant engineering (needs Core and Electrical foundation): equipment, valves, nozzles, instrumentation and control with ISO 10628-2 symbols; from 1.2.0 the ISA 5.1 symbols, the ISA tag rule and the line list attributes.
  • CFIHOS (needs Core, Electrical foundation and Plant engineering 1.1): 847 tag classes, 759 equipment classes, 1388 properties as attributes and 367 pick lists.

A package still in use is not switched off: E1 lists what uses it (see Switching packages on and off). Add a content package is greyed out; it comes with content package updates. Without the workspace server, a switch answers "Switching packages needs the workspace server."

Alex knowledge: your company's conventions

AvailableSince 2026-11-06Updated 2026-11-07LIB-alex-knowledge

Here your standards owner gives Alex your company's engineering documents. Alex proposes conventions from them; accepted ones Alex follows and marks Company convention. Team memory lets Alex learn usual values from your projects. The full guide is in Alex.

Where
Configuration → Alex knowledge
Who
Adding and removing documents: Engineering standards owner, Library administrator or Owner. Accepting conventions and Team memory: the permission to approve conventions.
Before you start
A company standard as .pdf, .docx, .xlsx, .xlsm, .txt, .md or .csv.

Steps

#ActionExpected result

Catalog import

AvailableSince 2026-11-07Updated 2026-11-08LIB-catalog-importRoadmap 20.5Review check L19

Import a vendor list from Excel or CSV into a catalog instead of entering each item by hand. A dry run shows first what each row would become; the import makes drafts only, which you then publish.

Where
Configuration → Catalogs → a catalog → Import…
Who
Company catalogs: Owner, Library administrator or Catalog maintainer. Project catalogs: Project administrator. A catalog from a content package is read only and has no Import….
Before you start
A project is open and a catalog exists (see Catalogs). A vendor list as .xlsx or .csv with the columns Manufacturer, Model, Ordering code and the class's attributes, for example "Flow rate [m³/h]".

Steps

#ActionExpected result
1Open the catalog "Approved pumps" and click Import….The panel "Import a vendor list" opens with the note "An Excel workbook or CSV with Manufacturer, Model, Ordering code, and the class's attributes as columns (a unit in brackets, "Flow rate [m³/h]", applies to plain numbers). Rows are matched to this catalog's items by manufacturer and ordering code. Import makes drafts only.", a File picker, Class of the rows and the buttons Dry run, Import and Close. Dry run and Import are off until a file is chosen.
2Choose the vendor list under File.Dry run and Import turn on.
3In Class of the rows, choose Centrifugal pump.Every row will be of this class. Leave it on From a Class column when the file has a Class column.
4Click Dry run.A line reads "Dry run: N new, N new versions, N unchanged, N refused.", and a table lists each row with Line, Manufacturer, Model, Ordering code, Result (New, New version, Unchanged or Refused) and Why. A Columns box shows how each column of the file is read. Nothing in the catalog changes.
5In Columns, set a column you do not want to Leave out, and click Dry run again.Each column offers Leave out, Manufacturer, Model, Ordering code, Description, Class and, when it matches one, "Attribute: …". The new dry run reads the file with your choices.
6Click Import.The line reads "Imported as drafts: N new, N new versions, N unchanged, N refused." The new items are listed with Status Draft; refused rows are left out. Import turns off and a button Publish N drafts appears.
7Click Publish N drafts.The line starts with "Published." and the items are listed as Published, each with its version.
8Click Close.The panel closes.

A row whose manufacturer and ordering code match an item of this catalog becomes a new version of it, or stays unchanged when nothing differs. A refused row says why in Why, for example a value in a unit that does not fit the attribute. Choosing another file clears the result and the column choices.

A long import may say "The import is taking long; look again in a moment."; the items appear in the catalog once it is done.

This runs as a job on the server, which may wait its turn first when the server is busy. At most 20 jobs a minute per person, else You started more than 20 jobs in a minute; wait a minute and try again.
